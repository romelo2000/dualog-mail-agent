# Dualog -> Gmail Mail Forwarding Agent

Локальный агент, который опрашивает почту Dualog по IMAP, отбирает "важные" письма
по простым правилам (отправитель / тема / ключевые слова) и пересылает их на Gmail
через SMTP. Работает независимо от Thunderbird — Thunderbird можно не закрывать,
это отдельное IMAP-подключение к тому же ящику.

## Требования

- Python 3.10+
- Данные IMAP-аккаунта Dualog (те же, что в Thunderbird)
- Gmail-аккаунт с **паролем приложения** (App Password), НЕ обычный пароль

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и заполните:

- `DUALOG_IMAP_HOST` / `DUALOG_IMAP_PORT` / `DUALOG_IMAP_USER` / `DUALOG_IMAP_PASSWORD`
  — посмотрите в Thunderbird: **Настройки учётной записи → Сервер входящей почты**
- `GMAIL_SMTP_USER` — ваш Gmail-адрес
- `GMAIL_SMTP_APP_PASSWORD` — пароль приложения из
  https://myaccount.google.com/apppasswords (требует включённой двухфакторной аутентификации)
- `GMAIL_FORWARD_TO` — куда пересылать (обычно тот же Gmail-адрес)

## Настройка правил важности

Файл `rules.yaml` — редактируйте под свои нужды:

- `senders` — адреса/домены отправителей, письма от которых всегда важны
- `subject_keywords` — ключевые слова в теме письма
- `body_keywords` — ключевые слова в теле письма
- `exclude_senders` — отправители, которые исключаются даже при совпадении (спам/рассылки)

Сравнение — регистронезависимое вхождение подстроки.

Файл перечитывается автоматически перед каждым циклом опроса — можно редактировать
`rules.yaml` (обычным блокнотом) прямо во время работы агента, без перезапуска.

## Запуск

```bash
python main.py
```

Агент будет работать в бесконечном цикле с интервалом `POLL_INTERVAL_SECONDS` (по умолчанию 5 минут),
логировать всё в `logs/agent.log` и консоль. Остановка — `Ctrl+C`.

Для постоянной работы на судовом ПК рекомендуется запускать как службу/автозапуск
(например, через `launchd` на macOS или `systemd`/Task Scheduler на других ОС) —
могу настроить отдельно при необходимости.

## Гарантии стабильности

- Все сетевые вызовы (IMAP, SMTP) имеют **timeout**
- До 3 **retry** попыток с задержкой при сбое соединения
- **Watchdog**: если обработка одного цикла превышает `CYCLE_WATCHDOG_SECONDS` (120s по умолчанию),
  цикл принудительно помечается как `failed`, процесс не зависает и переходит к следующей итерации
- Каждое письмо помечается обработанным (`state/seen_uids.json`) только после успешной пересылки
  или после решения "не важно" — при сбое пересылки письмо будет повторено в следующем цикле
- Полное логирование: старт/конец цикла, найденные письма, решения фильтра, ошибки, retry, timeout

## Структура проекта

```
config.py         # загрузка .env и rules.yaml
logger.py         # настройка логирования в файл + консоль
state_store.py     # хранение UID уже обработанных писем
classifier.py       # логика "важности" по правилам
mail_fetcher.py      # IMAP-клиент (Dualog) с timeout/retry
mail_forwarder.py     # SMTP-клиент (Gmail) с timeout/retry
main.py           # главный цикл с watchdog
rules.yaml         # правила фильтрации (редактируется пользователем)
.env.example        # шаблон конфигурации, скопировать в .env
```
